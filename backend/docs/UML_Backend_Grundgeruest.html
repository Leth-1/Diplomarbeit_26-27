Erklärung: Ara.Core

Benutzer Konten/Benutzer.cs · erbt von IdentityUser<Guid>

Ein Konto in ARA, egal ob Studierende oder Personal. Von IdentityUser kommen schon E-Mail, Passwort-Hash, „E-Mail bestätigt“, Sperre usw.; wir ergänzen nur, was ARA zusätzlich braucht. Die Id ist eine Guid statt einer fortlaufenden Zahl, damit niemand IDs erraten kann.

MitgliedArtErklärung
+ Vorname : stringEigenschaftVorname der Person. Startwert "", damit er nie null ist.
+ Nachname : stringEigenschaftNachname der Person.
+ ErstelltAm : DateTimeOffsetEigenschaftZeitpunkt der Registrierung, in UTC gespeichert.
(geerbt) Id, Email, UserName, PasswordHash, EmailConfirmed, LockoutEnd, …EigenschaftenKommen von IdentityUser und werden von Identity selbst befüllt. Nie direkt setzen, sondern über den UserManager.

Rollen Konten/Rollen.cs · static

Die zwei Rollen aus dem Lastenheft (F02) an einer einzigen Stelle. Wer eine Rolle braucht, schreibt Rollen.Personal statt "Personal", so gibt es keine Tippfehler.

MitgliedArtErklärung
+ Studierende$ : stringKonstanteName der Rolle für Studierende: "Studierende".
+ Personal$ : stringKonstanteName der Rolle für das Ordinationspersonal: "Personal".
+ Alle$ : IReadOnlyList<string>FeldListe beider Rollen. Wird beim Start verwendet, um fehlende Rollen anzulegen. Nur lesbar, damit niemand zur Laufzeit Rollen dazuschreibt.

Erklärung: Ara.Infrastructure

AraDbContext Persistenz/AraDbContext.cs · erbt von IdentityDbContext

Die Brücke zwischen C#-Objekten und der SQLite-Datenbank (Entity Framework Core). Weil er von IdentityDbContext erbt, hat er schon alle Tabellen für Benutzer, Rollen, Logins und Tokens (AspNetUsers, AspNetRoles, …). Julius ergänzt hier später DbSet<Buchung> usw.

MitgliedArtErklärung
+ AraDbContext(DbContextOptions<AraDbContext> options)KonstruktorBekommt die Einstellungen (welche Datenbank, welche Verbindung) von außen. In der API kommen sie aus AddInfrastruktur, in den Tests aus DatenbankTest. Geschrieben als Primärkonstruktor direkt hinter dem Klassennamen.
# OnModelCreating(ModelBuilder builder) : voidMethode (override)Wird von EF Core einmal aufgerufen, um das Datenmodell zu bauen. Zuerst base.OnModelCreating (Identity-Tabellen), danach ApplyConfigurationsFromAssembly: Alle Klassen, die IEntityTypeConfiguration umsetzen, werden automatisch gefunden. Neue Tabellen braucht man hier also nicht einzeln einzutragen.
(geerbt) Users, Roles, UserRoles, …DbSetsZugriff auf die Identity-Tabellen, z. B. Db.Users.Add(...) im Test.

SqlitePragmaInterceptor Persistenz/SqlitePragmaInterceptor.cs · erbt von DbConnectionInterceptor

Ein „Abfänger“: EF Core ruft ihn jedes Mal auf, wenn eine Verbindung zur Datenbank geöffnet wurde. Dann schickt er drei SQLite-Einstellungen (PRAGMAs) ab.

MitgliedArtErklärung
- Pragmas$ : stringKonstantejournal_mode=WAL: Lesen und Schreiben gleichzeitig möglich. busy_timeout=5000: bei belegter Datenbank bis 5 Sekunden warten statt Fehler. foreign_keys=ON: Verweise zwischen Tabellen werden geprüft (in SQLite sonst aus).
+ ConnectionOpened(DbConnection c, ConnectionEndEventData e) : voidMethode (override)Wird nach dem Öffnen einer Verbindung im synchronen Fall aufgerufen. Erstellt einen SQL-Befehl mit den Pragmas und führt ihn aus.
+ ConnectionOpenedAsync(DbConnection c, ConnectionEndEventData e, CancellationToken ct) : TaskMethode (override)Dasselbe für den asynchronen Fall (await). Beide werden gebraucht, weil EF Core je nach Aufruf (SaveChanges oder SaveChangesAsync) die eine oder andere verwendet.

DependencyInjection DependencyInjection.cs · static

Sammelstelle für alles, was Ara.Infrastructure beim Start anmelden muss. So muss Program.cs nur eine Zeile aufrufen und die Details bleiben in diesem Projekt.

MitgliedArtErklärung
+ AddInfrastruktur(this IServiceCollection services)$ : IServiceCollectionErweiterungsmethodeMeldet den SqlitePragmaInterceptor (einmal für die ganze Anwendung, Singleton) und den AraDbContext an. Die Verbindungszeichenfolge ConnectionStrings:Ara wird erst gelesen, wenn ein Context gebraucht wird; dadurch können die Tests sie durch eine In-Memory-Datenbank ersetzen. Fehlt sie, gibt es eine klare Fehlermeldung. Gibt services zurück, damit man weitere Add...-Aufrufe anhängen kann. Später kommen hier Zahlung, E-Mail und Dateiablage dazu.
+ InitialisiereDatenbankAsync(this IServiceProvider services)$ : TaskErweiterungsmethodeLäuft einmal nach dem Start. Erstellt einen Scope (weil der DbContext pro Anfrage gedacht ist), spielt mit MigrateAsync alle fehlenden Migrationen ein (legt die Datei ara.db an, falls es sie noch nicht gibt) und legt mit dem RoleManager jede Rolle aus Rollen.Alle an, die noch fehlt. Mehrfaches Starten ist also problemlos.

Migrationen Persistenz/Migrationen/ · automatisch erzeugt

Werden mit dotnet ef migrations add erzeugt und nicht von Hand geschrieben. Sie sind die „Versionsgeschichte“ des Datenbankschemas.

MitgliedArtErklärung
Start.Up(MigrationBuilder b) : voidMethodeLegt alle Identity-Tabellen an (AspNetUsers mit Vorname, Nachname, ErstelltAm usw.).
Start.Down(MigrationBuilder b) : voidMethodeMacht Up rückgängig (löscht die Tabellen wieder).
AraDbContextModelSnapshot.BuildModel(ModelBuilder b) : voidMethodeAktueller Stand des Modells. EF Core vergleicht ihn bei der nächsten Migration mit dem Code und erkennt so die Änderungen.

KontenController Controllers/KontenController.cs · erbt von ControllerBase

    K->>U: GetRolesAsync(benutzer)
    U-->>K: ["Studierende"]
    K-->>F: 200 OK, IchAntwort als JSON
  end
